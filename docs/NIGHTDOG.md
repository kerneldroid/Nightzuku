# NightDog — Единый фоновый демон и менеджер обновлений Nightzuku

## Архитектурный выбор: почему оставлен NightDog вместо WorkManager

Для фонового мониторинга и обновлений модулей выбран и расширен **NightDog** (`NightDog` на стороне `shizuku_server` + `NightDogClient` в процессе менеджера) вместо `androidx.work:work-runtime`:

1. **Прямая привязка к жизненному циклу `shizuku_server`**: установка и обновление модулей требуют живого привилегированного Binder-соединения (`uid 0` / `uid 2000`) для записи в `/data/local/tmp/nightzuku/modules`. `WorkManager` запускается ОС по собственному расписанию даже при остановленном сервере и жёстко режется OEM-ограничениями (`App Standby Buckets`, Xiaomi/MIUI, Samsung/OneUI, Huawei, Realme).
2. **Нулевой оверхед**: не требуется тянуть в APK `androidx.work`, `Room` и фоновые `JobService`, создающие лишние SQLite-базы.
3. **Мгновенный триггер `ON_START`**: как только пользователь или автозапуск поднимает сервер, `NightDogClient` получает `onServiceStatusChanged(running = true)` и при настройке `При запуске сервера` сразу выполняет проверку/обновление.

## Настраиваемые и опциональные обновления модулей

Все параметры обновлений хранятся в `ModuleSettings` и настраиваются пользователем на экране **«Обновления и источники»** (`UpdateSettingsScreen`), а также непосредственно в карточках модулей (Phone / Android TV / Wear OS):

- **Частота фоновой проверки (`UpdateFrequency`)**:
  - `Никогда (вручную)` (`never`) — фоновые проверки полностью отключены.
  - `При запуске сервера` (`on_start`) — проверка выполняется один раз при старте `shizuku_server` и по кнопке вручную.
  - `Каждые 6 часов` (`6h`), `Раз в день` (`24h`, по умолчанию), `Раз в неделю` (`168h`).
- **Автообновление модулей в фоне (`auto_update_modules`, по умолчанию `false`)**:
  - Если включено, `NightDogClient` автоматически скачивает и устанавливает найденные обновления и перезапускает `service.sh` для активных модулей.
- **Только по Wi-Fi / безлимитной сети (`update_wifi_only`, по умолчанию `true`)**:
  - Проверяет `ConnectivityManager` (`NET_CAPABILITY_NOT_METERED` / `TRANSPORT_WIFI` / `TRANSPORT_ETHERNET`) перед выполнением фоновых сетевых запросов к GitHub API.
- **Уведомления об обновлениях (`update_notifications`, по умолчанию `true`)**:
  - Отправляет системное уведомление в канал `nightzuku_module_updates` о найденных обновлениях или об успешном фоновом автообновлении с быстрым переходом в `ModulesActivity`.
- **Заморозка версии (Pin / Ignore updates per module)**:
  - Любой модуль можно заморозить на текущей версии кнопкой «Заморозить версию» (чип `Версия заморожена`). Замороженные модули пропускаются при фоновом автообновлении и пакетном обновлении «Обновить все».
- **Пакетное обновление и интерактивный диалог обновления**:
  - Кнопка **«Обновить все (N)»** с прогресс-баром обновляет все доступные модули за один проход.
  - Нажатие на бейдж обновления открывает диалог с переходом версий (`vCurrent → vLatest`), списком изменений (`Changelog` из GitHub Releases / коммита), выбором режима (`По умолчанию` / `ZIP-релиз` / `Из исходников`) и кнопкой заморозки.
- **Атомарный бэкап и авто-откат (`AdbModuleManager`)**:
  - Перед заменой каталога модуля создаётся резервная копия `<id>.backup`, переносятся `.source.prop` и маркер `disable`. При любой ошибке автоматически восстанавливается рабочая версия.
